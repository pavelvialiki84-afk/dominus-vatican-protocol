# DOMINUS — Revenue Operations (approved 2026-11-21)

Owner: Pavel Velichii. Source of truth for **sales and earned royalties**: the store dashboards / dated exports, never social metrics or static website labels.

## First live baseline
- The public `editions.html` advertises 11 available Amazon formats (EN/DE/FR/IT/ES) and one EN hardcover draft; this is **only a website claim**. No store-dashboard check was performed here.
- The site's `assets/analytics.js` currently loads a Metricool tracker unless DNT/GPC is active; it pushes Amazon-click events to `dataLayer` **only if already present**. That is not a verified purchase event or complete store-click measurement. `analytics-privacy.html` documents this limited capability.
- Amazon Store status, price, royalty, ISBN, uploaded files and print pages require KDP evidence. The registry intentionally leaves these blank.

## Revenue gates — complete in order
1. **Catalog master**: reconcile every row of `catalog_master.csv` with KDP Bookshelf, KDP Reports, local manuscript release manifest and public product page. Record `last_verified_at` plus protected evidence reference. If an eBook is enrolled in KDP Select, audit exclusivity before Kobo/Google Play distribution.
2. **Link quality**: audit `read.html`, `editions.html`, each language landing page and each Amazon ASIN for public 200, right language/format, correct price and real checkout availability. Fix P0 before creating new ads.
3. **Attribution**: label outbound acquisition URLs generated by `utm_links.py`; retain the tags on site navigation and collect counts in privacy-compliant analytics only when legally implemented and tested. Click to store != sale. No new analytics pixel is installed by this change.
4. **Events** (proposed, not implemented): `landing_view`, `opening_start`, `opening_progress`, `dossier_view`, `edition_select`, `store_click`. Guard against double-counting; use consent where required under EU/German law; document actual recipients and data flows.
5. **Sales**: fill `sales_weekly_template.csv` from dated seller exports, per currency and format. `units`, `royalties_earned`, `royalties_paid`, `refunds` are distinct. `UNKNOWN` is never zero.
6. **Marketing discipline**: use one `creative_id` for each concept/variant, record planned/published/error status; schedule 3–4 IG / 2–3 FB / 4–5 Threads / 5–7 Pinterest unique pieces per week only when the network works. No cross-posting duplicates just to fill a quota.
7. **Weekly decision**: compare channel -> opening engagement -> store CTR -> verified sales (where actually attributable), pause failing publication infrastructure, improve weaker reader CTAs, scale only after adequate comparable sample.

## UTM rules
- `utm_source` = `instagram,facebook,threads,pinterest,tiktok,youtube,substack,reddit,goodreads`.
- `utm_medium` = `organic_social`, `organic_video`, `newsletter`, `community`, `referral`.
- `utm_campaign=schism_launch_2026q4`; `utm_content` = lowercase stable creative identifier (e.g. `latin_hook_en_v01`). No personal information in URLs.
- **Do not** UTM-tag internal navigation or pretend direct/Google Organic URLs were campaign referrals. Search/direct classification belongs to analytics.
- Landing destination must remain `dominusbooks.com`; store button events and KDP reports are separate data sources.
- Any analytics code change requires legal/privacy QA first. Avoid claiming an anonymous, non-cookie service automatically satisfies all consent obligations.

## Canon / claims gate
Never market DOMINUS as a confirmed conscious AI, a supernatural proof, or as sponsored/endorsed by the Vatican. Key tension: humans granting machine-generated testimony the final word over a person. Date: 11 November 2035. No fabricated quotes, ratings, endorsements or sales numbers.

## Legal audit blocker
Confirm a legally usable Impressum/service address, privacy notice, third-party tracker disclosures, consent if needed, accessible footer links, and contact route without publishing an unapproved private residence. Existing `analytics-privacy.html` is not necessarily a complete privacy policy.

## Evidence / security
Do not commit store reports containing customer data, passwords, credentials, billing records, addresses or tax IDs to this public repository. Keep actual commercial exports in a private workspace; this public repo contains **templates and website-listed ASINs only**.
